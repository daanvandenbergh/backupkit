Restoring copies one snapshot out of the archive to a fresh path you pick. It never writes into an existing directory and never deletes anything, so a restore cannot damage the archive or an existing tree.

**You need:** a target with at least one complete snapshot. Check with `backupkit list`.

## Restore a snapshot

Give `restore` the target, the snapshot name, and an `--output` path that does not exist yet:

```bash
backupkit restore var-www 2026-08-10T031500Z --output /tmp/restored-www
```

On success it prints one line naming the target, the snapshot, and where it landed.

The copy runs `rsync -a --sparse -H`, so permissions, sparse files, and hard links inside the snapshot are preserved. Symlinks are copied as symlinks and never followed. `--delete` is never passed - restore only ever writes into a fresh path.

## Restore the latest snapshot

Pass `latest` instead of a name to get the newest complete snapshot. The CLI and the library resolve it the same way:

```bash
backupkit restore var-www latest --output /tmp/restored-www
```

Name a snapshot that does not exist or is not complete, and restore refuses and tells you the newest complete snapshot for that target, so you can retry with a valid name.

## Where you can restore to

The `--output` path must not already exist - there is no restore-into-existing mode.

Its parent directory does have to exist, and that parent must not resolve inside any configured destination root. Restoring on top of, or inside, an archive is refused outright, so a restore can never overwrite the snapshots it is reading from. Pick an output path outside every archive.

## Verify the copy

Add `--verify` for an integrity check after the copy. It runs a checksum comparison between the snapshot and the restored tree; if any file differs, the restore fails and lists the differing paths.

```bash
backupkit restore var-www latest --output /tmp/restored-www --verify
```

A clean pass marks the output line as verified.

It is opt-in because it re-reads both sides in full. Skip it for a routine restore; use it when you need proof the copy is bit-for-bit identical.

## Restoring from the library

The CLI is a thin layer over `Backupkit.restore()`, which returns a `RestoreReport`:

```ts
import { Backupkit } from "@daanvandenbergh/backupkit";

const kit = Backupkit.fromConfig();
const report = await kit.restore({
    target: "var-www",
    snapshot: "latest",
    output: "/tmp/restored-www",
    verify: true,
});
// report: { target, snapshot, output, verified }
```

The same rules apply: `snapshot` accepts `latest`, `output` has to be a fresh path outside every archive, and `verified` is `true` only after a clean verify pass.
